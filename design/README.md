# design/

System design and architecture work, once the model is stable.

**Belongs here:** system design documents, architecture options and trade-offs,
component boundaries, storage design, interface design, low-level foundations.

**Does not belong here:** final commitments made casually — anything binding
gets a record in `decisions/`.

Split into subdirectories (`design/architecture/`, `design/storage/`, ...) only
when flat files stop being enough.
